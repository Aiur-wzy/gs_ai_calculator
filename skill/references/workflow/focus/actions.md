# 动作工作卡

`action_checkpoint`。需要建动作、找空档或调整时序时读这张卡。先确认用户锁定的是动作、顺序、时点，还是其中几项。自主优化使用仍可调整的部分。

1. 按实际玩家操作写动作与稳定 ID，记录角色、变体、开始、施放占用、允许取消点、切人和等待。连续三次按键分别写成动作，按[连段](../../app-mechanics/actions/cast-sequences.md)核对续段窗口和基础冷却。时长、能耗、CD 未查清时保留待核。
2. 按[排轴原则](../../mechanics/rotation.md#二循环时长的构成)求最早合法衔接，检查脱手尾伤、允许取消点和相邻切人限制。需要等下一次附着、接球或技能次数时，分别比较切人时点与下一动作时点。可早切后等时，核前台收益和接球再决定。把实际时点、等待条件及收益记录下来。
3. 在同一用户目标下比较合法候选，采用可验证的改进。比如只要求一组至少一次触发时，按这项条件安排动作。保持固定顺序或时点，复核已继承的占用和等待，改轴后重算后续伤害、附着、Buff、冷却和能量。

发现动作卡住时，先查[动作与能量](../../app-mechanics/actions/rotation-energy.md)的占用、取消、次数和资源，再按[工作法](../index.md#遇到失败怎样继续)修正已授权部分。计算缺项期间仍可编辑和保存候选。需要确认后台事件时直接看[事件卡](events.md)。
