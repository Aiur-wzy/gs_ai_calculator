# 结果检查与交付工作卡

`calculation_closure`。需要定位一次失败、比较方案或交付实际结果时读这张卡。计算与诊断可在当前输入表示适用时执行。

## 失败后继续

先确认当前修订、组合状态、首个实际失败和执行到哪里。原生计算拒绝若保留了诊断，`details.execution_feedback` 给出执行状态及可见的失败摘要。按回执 `recovery.request` 查保存的执行。已执行前缀用于定位问题，未验证后段留待新执行。按[恢复路线](../index.md#遇到失败怎样继续)修改影响当前结果的最早问题。

已有自动结果与事实不符时，优先修输入或来源。确需接管时沿[精确覆盖](../../app-mechanics/review/overrides.md)限定范围并重算。只有无法表达且不改变后继状态的残余伤害，才考虑有来源的独立补充。

Q 失败时可用 `gs_diagnose_result`，传当前 `expected_revision` 与 `request={"view":"assistance","section":"energy"}`，核对失败时点、实际余额、缺口和已声明资源。支持的 `energy_trials` 可在副本上比较明确的 ER 与面板调整。先核来源和触发，再在授权预算内试配；试算回执只说明该副本的实际执行。入口与参数见[补正](../../app-mechanics/review/corrections.md#可选辅助视图与er试算)。

## 核对用户目标与优化结果

1. 依据[统计窗口](../../app-mechanics/review/report-window.md)核截止、伤害与分母、必需验证和可选尾审计。一个显式有限窗口可含多个游戏轮。逐次 Q 核能量，多轮继承冷却、次数、粒球、元素、Buff 和资源。稳态按相应合同另证。
2. 对照用户实际目标及已查的来源盘点，核每组动作、逐击替换或追加、后台首末跳和所有本场景拟采用的收益。已填写的效果有无执行是一项检查，技能、天赋、命座、装备、共鸣中是否漏写另一项是另一项；引擎不能凭已填列表证明没有遗漏。无需复制机械流水，可给每项保留已有输入/结果引用、明确不适用理由或待核状态。首次触发、刷新或到期、退场与续轮边界适合抽查，但抽样通过不能冒充完整覆盖。某组要求至少一次扩冰时，用该组的真实反应逐组说明。
3. 比较合法候选的用户目标与同口径结果。默认紧凑并主动优化 DPS，复核剩余等待是否改善接球、附着、收益或其他真实条件。说明优化范围和未验证的取舍，采用改动后用当前输入重新计算。

## 交付

先查看[任务对照](../task-evidence.md)：当前声明是否仍保留原题、哪些要求只有输入而没有执行证据、近似是否改变了用户想验证的机制。`task_evidence` 的差异是建议，不是新的准入门。已有记录为空也不证明完成；不要靠删除要求或改成“不适用”来清提示。真实阻断、尚未尝试、可自行修复和需要用户批准分别说明。

正式计算结果查看 `calculation_acceptance.status=accepted`，按实际回执报告已采用的近似和验证范围。材料化、覆盖和临时公共事实的实际消费仍需验证来源及唯一所有权。按[交付合同](../../outputs/app-and-excel.md)完成用户要求的产物。中文答复交代当前候选、已验证范围、未完成项、精确审核、同步和文件终态。已保存诊断和输入草稿可继续完善，正式应用仍由用户确认具体候选。
