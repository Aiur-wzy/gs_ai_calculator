# 配装工作卡

`loadout_draft`。需要选装备、核面板或分配词条时读这张卡。按[工作法](../index.md)保留用户锁定项。

1. 核实角色、等级、命座、武器、精炼和套装。区分用户给定的成品面板和需要按预算构造的面板。使用成品面板时，先确认其中已含哪些常驻属性。未知值保持待核。
2. 按预算构造时分别计入基础属性、武器、突破、花羽、主属性、副词条和常驻收益。基础攻击力和成品攻击力分别记录。按[面板口径](../../mechanics/artifacts.md)核主副属性互斥及聚合升级容量。保留用户给的等式与上限，预算内用充能替换输出词条。完整例子见[来源与结果对照](../coverage-and-review.md#从资料到输入和结果)。
3. 区分数值的来源和录入者：Agent代录用户面板与Agent自行构造是两种情况。当前支持`panel_provenance`时可保存这一信息和构造请求，组合/计算的`default_assistance`会给实际可核对范围。也可用 `gs_reference_panel` 单独比较面板。提供了预算上限时填写 `budget.total` 和 `budget.crit_total` 的适用项，实际总数等式另外核。`limits` 为空只统计用量；`exceeded=false` 表示没有超过已传入的上限。提示不改写候选、不强制调用工具。基础白值、武器成长与被动的查询分工见[装备](../../app-mechanics/loadouts.md)和[资料查询](../../data/query.md)。
4. 先为每次 Q 找到合法的能量方案。未指定产球情景时，按每次合格机会的平均粒数计算，保留概率来源和入账时点。再比较余下输出词条及充能转伤收益。初配可随动作和资源验证调整。角色资料按[附录配方](../../data/character-appendices.md)复用。

Q 不足时按[结果检查](closure.md#失败后继续)查失败前资源。有疑问时从[排轴资料索引](../../data/combat-references.md)核对应技能段的产球和回能，再调整可用词条或接球时点并重算。用户锁定面板时先核合法调时和已有资源路线，确需改面板再给具体差异。面板构造与动作设计可同时推进。
