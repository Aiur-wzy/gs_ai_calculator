# 数值工作卡

`numeric_model`。需要填倍率、属性、收益规则、时点或来源绑定时读这张卡。

1. 按实际组件选天赋等级、倍率、属性、单位和事件分类。分清面板已含常驻、战斗触发收益、属性转换和独立伤害。能量使用本次项目口径，结合实际动作、产球与到账核验。
2. 对每项会影响结果的收益核提供者、触发者、受益者、当前前台和敌方条件。再核作用于哪些伤害、进入哪个乘区、什么时候取值。施放快照和敌方当前状态可以并存。按[属性取样](../../app-mechanics/execution/attributes-and-sampling.md)表达已有证据的动态依赖。
3. 先查现有规则能否表达，必要时按[补正](../../app-mechanics/review/corrections.md)选支持的材料化或覆盖。采用[强类型材料化](../../app-mechanics/execution/materialization.md)时按其合同填实际消费对象、来源和绑定。直接原生规则可按对应规则合同建模。把同一收益或命中交给一个来源，补缺项后重新计算。
4. 以实际命中检查作用时点、取样值和伤害分项。用首次触发、续轮、刷新前后等有判别力的样本定位差异。两个独立的14%星超导基础增益同时适用时，`stellar_base` 加到28%，对应倍率1.28。其他同名来源是否叠加取决于实际刷新、互斥与乘区规则。

参数结构不清时沿[当前合同](../index.md#开始)读取作者 schema。收益没有命中时先核适用域、受益者和时间，再查原始规则。动态任务遇到缺依赖时补真实输入，见[继续工作](../index.md#遇到失败怎样继续)。
