# 来源采用、事件盘点与实际执行核对

## 1. 配装草稿与来源入口

先按项目目标填写角色等级、命座、用户/题面给定面板、武器及精炼、套装类型/件数、目标与初始状态。给定面板已含两件套等常驻属性，不重复加算；默认不构造五件主副词条；明确预算题面按授权构造并记录依据。基础天赋按[拉表原则](../../SKILL.md#拉表原则)取10级，仅将已激活对应加级命座的技能记为有效13级，并保留命座来源；不继承人工表的9级或其他参考条件。保存查询的完整`data_version`；版本标签不能独自证明正式服兼容。初次优先读取身份、basis和装备摘要并保存分实体入口；需要时按[equipment.md](../app-mechanics/loadouts.md)填写原生方案并compose，不由focus限制；成品面板不能反推出装备。

固定面板＋套装选择是当前默认输入，能完整交付原生方案；不能因缺少五槽就标为装备草稿。确实未选择任何武器/套装时可保留纯数值快照，并说明范围。仅继续旧完整装备模式才核对逐件输入，不虚构未参与公式的基础属性；需要 base 的效果只使用明确给定白值。

这里只建立各角色可用动作和专属来源入口。普通攻击、E、Q、特殊移动/派生动作、固有天赋、命座、武器效果、套装阈值和共鸣按当前依赖核对，只读本候选相关资料；会影响面板/动作的事实立即查，其余可在事件盘点时补，不以进入event_topology作为阅读前置。`talents`与`extra_info`按类别及来源识别；`buff_zone/effect_type`仅辅助定位，不替代正文与参数。

角色附录是默认读取项，先按[附录配方](../data/character-appendices.md)分批读所选角色的approved／pending正文并保存小资源，其他原文按上面的当前依赖查询。读取、采用和执行分开：未拥有命座或不适用事实可读后排除，pending不升权，也不因读到一条未知就自动建立阻断当前计算的来源。

| 来源记录 | 至少保留 |
|---|---|
| 身份与依据 | 持有角色、来源类别/ID、原文与参数位置、数据版本、所选等级/精炼 |
| 机制部件 | 伤害、增益、附魔、减抗、产球、固定回能、次数限制分别列出 |
| 处理结论 | 本候选采用及事实/动作引用；本场景不适用/明确排除及理由；资料或表达待处理。原生字段位置在转换时补入 |

未拥有的命座和生活效果可有依据地排除；未知不是未触发。装备 `effect_requirements` 只覆盖其实际列出的来源，不能当作全队技能、天赋与共鸣的完整清单。不要为获得 `ready` 批量排除条件效果。


## 2. 动作检查点

整理本队需要使用或评估的动作：E点按/长按、Q、普通攻击连段、重击、派生下落、冲刺/特殊移动、切人和等待。每种动作先记录身份、变体、占用或关键时点；缺实测时长记录假设，不把技能持续时间当施放占用。本阶段不证明CD、能量、产球和循环，也不因这些资料待填拒绝动作录入。

动作表保留稳定 ID、角色、类型/变体、开始、占用结束、关键触发/命中点、前台约束、目的与依据。E 与 Q 是两个动作；E 后派生下落另有动作；无伤害的附魔或切人同样保留。一条 `hit.skill` 分组或 `cast_t` 不等于动作实例。

根据用户目标安排再次E、辅助返场、普重击、切人和等待。用[排轴原则](../mechanics/rotation.md#二循环时长的构成)比较最早合法衔接和有依据的延迟，分别核切人、下一动作和后台时点。CD、接球和普重击回能按当前信息随时核查，未知保持待填。需要修正失败动作时保留用户锁定内容。


## 3. 每个动作检查全部触发来源

Agent根据角色资料盘点技能分量、天赋、命座和生命周期。按实际需要直接填写原生动作与事件，或用`event-topology-v1`辅助整理。引擎核对已声明节点及通用规则。采用材料化路径时，按该路径补实际执行绑定。

沿动作及其后续事件，依次核对技能本体 → 固有天赋 → 当前命座 → 武器 → 圣遗物 → 共鸣/队伍效果。明确触发条件究竟是按下、成功施放、命中、某元素伤害、暴击、反应、切人还是能量入账；后台后续命中也要在实际时点检查。持有者、实际触发者、受益者与当时前台可能不同。

| 增益/状态记录 | 要回答的问题 |
|---|---|
| 来源与触发 | 哪项原文部件，由哪个实际动作/事件满足条件？前后台、对象和元素符合吗？ |
| 数值与乘区 | 参数按所选等级吗？百分数是否转小数？平值加攻、比例面板与倍率后加算有无混淆？ |
| 属性取样 | 从哪个角色的 base/static/时变状态读取，在哪一时刻读取？装备改变后能否重算或要求复核？ |
| 时间与刷新 | 生效点、原文单次持续、刷新/叠加/离场规则、次数配额分别是什么？ |
| 受益范围 | 哪些角色、元素、伤害种类或精确事件受益？排除项有何依据？ |
| 落地与追溯 | 静态贡献、Buff 或独立伤害事件的位置及 ID；是否已预折入面板而重复计算？ |

原文单次时长与轴内连续覆盖分别保留。例如单次 10 秒、可刷新但不叠加的效果，在 2 和 4 秒实际触发，可连续覆盖 `[2,14)`；不能据此改写为“单次持续 12 秒”，也不能保留两条重叠加算 Buff。卡肉等修正只有有来源时才计入。

常规范围用 v2 的元素、伤害分类、收益类型及 `applies_to`。只有本轴出现分类范围无法表达的例外时，才用原生 `rotation_tuning.buff_hit_matches` 并保留理由、来源和确认指纹。match 是 Agent 对特定轴的微调，不替代引擎补来源、改数值或延长时间。

按实际规则确定范围与例外，用当前合同填写分类、ID和来源。用户授权可调的动作和时点在动作输入中修改，随后复核受影响事件和状态。


## 4. 闭合数值、能量与附着模型

计算使用当前动作、事件和数值。遇到格式、单位、引用或事件缺项时，修改对应输入。动作调整后更新有关映射与后续事件，见[工作法](index.md#建输入检查和改进)。

新机制模型用有依据的 `hit_patterns` 偏移和原型展开稳定多段，`hit_events` 关联单次命中；无需再手写展开结果。不同倍率、属性或附魔模式用不同原型。旧模板 `count` 只合并同条件伤害，不展开时间、ICD或次数配额；持续几秒不等于命中几次。

动作、产球、到账和扣能有不同语义。确定性产球/直接回能可由 v3 规则生成，引擎按实际到账时前台与各自 ER 计算；已有手工事件转自动时明确来源占有和替换ID，避免重复。怪物掉落、一次性与随机分支由Agent显式给情景，不能暗补。旧 v2 或未迁移部分仍按 [动作与能量接口](../app-mechanics/actions/rotation-energy.md) 声明事件。

已确认普通Q基础资源且运行时提供action_start扣能模式时，仅绑定模式并输入实际动作，禁止再逐动作复制spend。检查系统审计与成功父动作对应；失败、未验证和提前停止范围分别解释。审计不属于可执行事件，不能用于资源替换或额外收益触发；同刻后续返能不能补本动作开始时的门槛。

涉及反应时同时记录目标初态及逐攻击分量附着清单。每个实际命中分量须能定位动作/命中引用、元素、GU、`application_mode=sequence|no_icd|no_application|pending`、`icd.counter_tag`、`icd.rule_group`/完整序列与重置、目标、证据等级与来源；同一技能的初段/持续/终结、召唤物和命座追加攻击不能只靠技能名合并。伤害分类或普通/E/Q标签不能推断ICD，不同角色也不能套用另一角色的结论。缺`attenuationTag`或实际绑定时必须保持`pending`并补查，不能自动归为`no_icd`或`sequence`。

伤害元素、附着尝试、`application_allowed`、实际附着和最终反应是不同层。先核对counter状态与本击序列位置，再核对命中前元素底；允许附着但无可反应元素底时不会发生反应，同一技能也并非每跳附着。按当前[元素运行时](../app-mechanics/elements/runtime.md)能力提供有证据的档案，由受支持层计算每步元素底、ICD和反应，核对返回的前后状态。Agent预期仅作检查依据，不当作引擎答案；未知底不写成已知无附着。未支持的场景保留假设和范围，实验冻结模型保留参考等级。旧手工reaction不是元素模拟，自动反应与手填事件不得重复计伤。见 [reactions.md](../mechanics/reactions.md)。

角色自身、提供者和敌方状态分开。v3使用self/provider/enemy域和current/trigger/event采样，以实际取样回执核对；属性转换依赖另一转换时，按当前[属性接口](../app-mechanics/execution/attributes-and-sampling.md)支持的表达式与合法依赖图处理，不一概判为不支持。未知来源、不可分享属性、真实依赖环和未支持表达分别判断，不能为了消除缺项全部折成开场常数。旧模板`snapshot=true`会按cast_t读取整组Buff，包括敌方减益；不要继续用统一快照开关代替新分域声明。


## 5. 严格计算、双向检查与续轮

正向问“这次动作会触发哪些已选来源”，反向问“每个收益/伤害/能量事件由什么产生”。至少核对：

- 来源覆盖表是否有漏读/未知；每个临时收益都有合法触发、数值、时段和受益者，预折入面板的条件加成可定位和撤销。
- 一项效果有消费记录，不代表它覆盖了资料规定的全部伤害。先结合原文和细化机制证据确定适用类别；同属一个反应体系，不代表能力直伤和多人反应分量必然享有相同增益。对确实适用的各类实际事件分别抽查正例，再核一条不应受益的反例。没有该类实际事件时如实说明，不补造事件凑检查，也不为提高总伤擅自扩大范围。
- 每个命中有动作或持续效果来源；普重击的附魔有依据；检查引擎有限次数的前后余额及消费命中，不手工重新分配另一份次数。
- 每个反应相关命中都有附着清单记录；逐击回执分别展示`application_mode`、allowed与reaction。用同组跨动作、不同组交错、无ICD连击、明确无附着、资料pending、计时重置、有限序列耗尽和无对应元素底做对抗复放，不能只以最终融化次数正确判定ICD正确。
- 动作占用、切人、CD/充能次数与爆发资源一致，空档有取舍说明；不支持的体力、距离、命中等约束单独披露。
- 检查每次 Q 前的能量，不只看每轮总收入。下一轮继承能量、溢出损失、在途粒球、CD/充能次数、仍有效的 Buff 与已建模元素/ICD 状态。
- 首轮满能量只是初态。连续两轮无失败不自动证明无限稳定；分别报告首次失败、已验证轮数、周期边界是否收敛及未建模的随机分支。

分别给出“伤害数值结果”“动作检查”“能量检查”“附着/反应与机制覆盖”。`not_checked`、待处理、失败和受支持范围内通过不可互换；不可执行轴的计划伤害不能称可执行DPS。严格门禁失败只保存`diagnostic_attempt`，执行前缀不得作为正式结果。失败先判断是拓扑遗漏、数值/绑定错误、角色事实错误还是动作规划问题，保留候选修订并修复实际输入；不得暗改用户固定时点／动作、借能量或删除固定爆发来通过检查。

## 机制语义到执行输入


在排轴需要解释复杂动作、状态或收益时读取；纯数据问题不要求完成本页检查。只处理当前采用且影响结果的机制，复用已有角色资料和来源/绑定；原生查询资源只读，结论用实际finding或合法候选说明保存，外部Agent可按自身权限写小文件，不新建虚构资源写工具或第二份巨大台账。

## 一条来源怎样采用

先明确对象/组件、条件、效果、适用范围、时间基准和证据；这些不是看到一段倍率就能推导出来的。记录结论是已查证、用户场景假设、待核还是本场景明确不适用；资料存在、已读、已输入、已执行和已验证分别陈述。

原文/参数与Skill速查冲突时核对版本、上下文和数值用途，不用机器effect_type、训练记忆或“引擎没报错”裁决游戏事实。查当前DB正文/appendix和精确能力来源，必要时定向联网。pending知识按其来源状态使用，不能改名自称独立证据；实际采用的明确假设走当前允许合同并标注，不伪造reviewed。

## 从资料到输入和结果

这些例子用于判断当前怎么做。实际参数取当前资料，字段取对应工具合同。

| 已知条件 | 怎样建输入和检查 | 典型误判 |
|---|---|---|
| 总数38词，双暴合计最多30词，允许用充能换输出 | 写明总数等式与双暴上限。13暴率＋16暴伤＋9充能是38词、双暴29。核主副互斥，再查每次Q前能量和实测候选收益。 | 把初配30双暴留下的8词写成充能上限，或额外送充能词。 |
| 一项技能在合格命中时产球，并有共享触发间隔 | 依来源声明每次合格检查的数量、共享范围和到账；按当时前台、各接收者ER及溢出核对。Q失败后只统计到失败点的真实账目。 | 为通过下一次Q改已知球数，或把未执行后段的计划收入按秒外推。 |
| 多段伤害共享附着，任务需要每组至少一次实际反应 | 保存独立命中，填写有依据的附着组。逐组读实际元素底、附着许可、反应和领域结算。只有一段真触发也可满足“至少一次”。 | 用伤害段数代替附着次数，借另一组成功充数，或将尚未结算的累计层数填入直伤。 |
| 脱手攻击可刷新或换成另一种伤害 | 分别建施放占用、首末跳、刷新和取消。原组件被替换时只结算一种；有独立追加时保留额外事件。改轮距后按新时点核旧实例末跳。 | 等后台最后一跳才切人，或用不再发生的重召裁掉原本有效的尾伤。 |
| 一个收益限定本人、伤害域或目标状态 | 对照提供者、实际受益者、当前前台、伤害分项、取样和有效时段。抽查本应命中及本应拒绝的样本，确认实际收益值。 | 把本人后台写成仅前台，给普通伤害加仅反应的收益，或把零匹配当作已应用。 |

## 容易混淆的语义

| 描述或任务 | 应确认的输入 | 避免的错误 |
|---|---|---|
| “转为/替换/改为” | 同一个组件在条件下的替代路径、适用区间、对应倍率/体系、唯一所有者 | 保留普通伤害再加一次特殊伤害；只改中文名或元素但仍用原公式 |
| “额外造成/追加” | 独立组件、条件、次数/CD、时点和来源 | 随意删掉原组件；把所有额外描述都套为同一伤害区 |
| “提高伤害/视为某伤害” | 是面板加成、基础区加算、倍率乘算、体系转换还是独立事件 | 看一个“提高”就当普通增伤，或把倍率标签当反应答案 |
| “持续/周期/脱手” | 施放占用、首末命中/周期、何时可接下一操作、换人/取消后的存续 | 等最后一跳后才允许下一操作，或反过来把施放占用设0 |
| “续段窗口” | 输入的最大有效间隔、最低间隔若有证据、次数/冷却起算 | 把4秒内可续段写成每段必须等4秒；不确认就补0CD |
| “每X次/每Y秒/刷新” | 计数或计时的是命中/附着/反应/消耗中的哪一项，共享范围和重置规则 | 几种计数混用；将刷新窗口叠加成双份收益 |
| “快照/动态” | 哪个属性/收益、在何时取样、持续多久，敌方状态是否另行动态 | 只凭脱手锁全部面板；把属性快照顺便扩展为敌方减抗快照 |
| “充能达到增伤上限” | 收益映射与上限；另有每次Q前资源账 | 用收益封顶代替能量够用，或认定ER一定没有伤害收益 |

没有证据的采样/取消/命中时点保持待核；“可脱手”只能支持持续与动作占用分离，不能自行发明帧数、快照或全部中断规则。

## 按情况选用的软检查

这些提示用于初步构建时辨别机制，以及计算后定向复核；不是新增阶段门、固定表格或每轮必须重做的全套任务。只检查当前采用且会影响结果的来源，复用已查明的资料与实际回执。

| 遇到的情况 | 初步构建时留意 | 算后优先核对 |
|---|---|---|
| 给定成品面板／从预算构造面板 | 成品面板核对已含范围；预算构造分清基础、武器副属性、主副词条及花羽等固定项，不因一个数字缺失就反推或改用户面板 | 提交值与组成是否一致，遗漏与重复加算是否同时排除；参考面板只作辅助 |
| 面板加成／比例分享／属性转换 | 提供者和受益者可能不同；先分固定值、比例所用基数、封顶，再查初始、施放、触发或实时取样；已含常驻与战斗收益分账 | 在提供者属性变化或增益到期前后，实际采用值是否按声明变化或保持快照；转换输入来源及可继续分享资格有无混淆 |
| 有限多段／固定周期／条件触发攻击 | 分清首跳基准、次数或终点边界、触发条件，以及普通／特殊伤害的替换或追加；施放占用不等于出伤持续 | 对同一动作实例和通道核对首末时点、次数、归属；漏跳、双发、合法取消、未命中和窗口外尾段分别解释 |
| 切人／重新施放／刷新或替换 | 生命持续时间、攻击时钟和ICD共享计数可能分别处理；只按该来源有据的规则续存、重开、暂停或销毁，不套一个通用刷新结论 | 旧实例何时停止、新实例何时首跳、是否重叠；第二轮是否正确继承仍存在的实例与共享计数 |
| 多段元素伤害／反应／领域收益 | 每段伤害不等于每段附着；不同名字不证明独立计数，相同模板也不证明共享。周期结算型区分建场、合格计层、待结算累计与已结算增益；即时／持续型按自身状态处理 | 先看命中前状态，再看附着许可与实际反应；周期结算型按对应领域最近已完成结算核对，即时／持续型按实际生效状态核对，不用目标反应、最大层数或预期覆盖代填 |

不确定时先定位“资料未查清”“还未输入”“已输入但未执行”或“执行后未应用收益”。从第一个不符的组件向前追查，再更新受影响后继；不要一看到低伤害就认定引擎错，也不要因为有一条结果就认定机制齐全。对当前高影响未知做定向查询或明确近似，不靠全量重读和增加硬性禁令替代判断。

## 动作、效果和伤害分开

玩家操作可以产生即时/延迟/周期命中、Buff、状态、附着尝试、资源及其它派生。多个组件可共享父动作，也可在玩家开始下一动作后继续；按已核生命周期决定。初编辑可先录骨架，参数不足不阻止保存；正式结果前再闭合实际消费项。

一次命中不必附着，一次附着许可也不保证发生反应。伤害元素、GU、ICD组、实际元素底和反应各自声明/读取，不能用普攻/E/Q分类推断ICD共享。标准和特殊规则复用当前通用接口，证据不足不默认1U、无ICD或必融化；详细规则读[反应](../mechanics/reactions.md)。

需要逐段取样、消耗次数、触发/附着或改变后继时，保留独立时点和稳定ID；不能只因倍率相同合并count。只有条件与取样一致、不丢失状态/触发语义时才做数值聚合。用户规定的段数要落到对应组件，不能把普攻段数、重击次数与每次派生束数互相代替。

## 在现有小资源中保留最小采用记录

对本候选相关来源，保留“事实/来源引用→适用条件→组件/输入位置→采用或有据排除或待核”。可以是短表或紧凑字段，不要求逐角色复制全文。

建立附着和周期输入时，逐组件把已采用资料中的元素量、共享身份／计数标签、规则模板、序列／重置、首发／周期／相位与实际声明核对。两个伤害、不同实体或不同名字不证明独立附着；仅共享模板也不证明共享计数。来源只支持部分字段时标明剩余未知与敏感性，不能把本地明确相反的机制伪装为普通assumed近似，也不能选偏移来制造目标反应。

- 已采用：指出实际事件/规则/绑定，不能只在备注声称有Buff。
- 明确不适用：说明用户配置/动作/状态为何不满足；未知或未实现不算未触发。
- 待核/表达未完成：指出影响范围和下一查询/补源目标，不填0冒充无影响。

不能因为自动来源不覆盖、接口较复杂或估计剩余时间不够，直接把已确定可触发的战斗增益记为“不适用”。先查完整原生规则、Buff、属性及目标条件接口能否表达；能表达则完成真实输入，确实未完成时保留具体缺项与当前结果影响，不让有总伤代替游戏任务完成。辅助预期盘点用于发现遗漏，不另设强制台账门槛。

角色技能、有效天赋/命座、武器、套装和共鸣按当前相关性盘点。复用已查明资料，变化后只复核受影响来源；原文与已采用摘要的差异及时纠正，不要求所有生活/未启用效果都建事件。

## 算后对照

先看实际首个拒绝和已执行窗口；再对照采用记录与当前结果，检查组件数/首末时点、替换与追加归属、Buff接收者、逐Q能量和附着/状态。每一条结果应有来源，每一个采用且应发生的组件应有实际执行或明确拒绝原因。

触发或激活不等于收益已被目标伤害消费。对预期生效的来源核对最终消费及其真实数值，零消费时查时段、角色、事件类型与筛选原因；资源或状态来源则查对应账，不要求它们出现在伤害收益列表。叠层查实际层数及刷新／到期，不能从max推满层；独立乘区分清增幅与乘数、加法与乘法的中性值。可批量读取同源摘要，不为此重复查询全部角色资料。

面板、动作或资源修改后，敏感性和最少词条等对照也须从最终输入更新；简化投影应说明保留了哪些当前动作、原始资源和派生固定返能，不用旧版本对照冒充最新完整模型的证明。

计数相同不等于正确：可能用了错误体系、倍率、时点或状态。App结构/数值/绑定通过也不证明角色全机制完整。修最早错误及其依赖，fresh重算；不能用后续预期填补尚未执行的事件，不能让计划伤害成为正式DPS。详见[补正](../app-mechanics/review/corrections.md)。

按实际用户目标逐组检查命中前状态、附着许可、真实反应及收益触发。例如要求每次AE至少一次扩冰时，每组各自定位实际父动作和反应，不能用另一组的成功或风伤本身充数。附着被ICD阻断不等于该次伤害被删除；伤害数、附着尝试、获准附着与合格领域计层分别对账。动作／规则改变后重建受影响手工条件并fresh重算元素底、领域、共鸣、风套、资源与伤害，不继承旧结果资格。
