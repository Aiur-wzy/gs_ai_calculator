# 当前任务工作法

适用于 `workflow=artifact`。配装、动作、事件、数值和结果检查是五个工作重点，不是权限状态。按当前问题选卡，可交错编辑、查证和计算。工作重点改变阅读建议。工具是否适用取决于实际输入表示、身份和授权。

## 开始

1. 确认本次目标、固定项、可调范围和交付要求。读取当前候选摘要，按实际内容区分空白板和旧方案。使用用户给的成品面板，或按用户明确的主属性与词条预算构造。保留等式与上限。按[白板接续](whiteboard.md)处理用户已有文档。
2. 原生用 `gs_read_context` 读取 `capability_index`。工具参数在 `tool_contracts` 的 `/tools/工具名`，资料查询动作在 `runtime_contracts` 的 `/actions/动作名`，调用 `gs_query_runtime` 时将真实 `action` 放进 `request`。方案外层字段在 `plan_schema`，动作、机制和效果绑定沿目录 `/plan_contract/native_details/authoring_sections` 读取。复制相应入口的 `resource` 和 `pointer`。独立 CLI 和连接 App 的 CLI 见[入口与资源根](../runtime/software-entrypoints.md#三种入口的资源根)。
3. 选定角色后按[附录配方](../data/character-appendices.md)读完全部可读正文，复用同快照资料。判断已选武器和套装触发时查[装备附录](../data/query.md#查询已选装备的资料附录)与实际精炼、套装原文。资料确有疑点且已开放研究时，定向核实并登记[研究账](../data/research.md)。

## 建输入、检查和改进

多条件任务保留原题和当前差异，按[任务对照](task-evidence.md)区分原话、自己的解释与实际证据。只需记录影响结果的判断；不要求先完成台账才允许计算。用户已授权的可修工作应继续，不因为模型一轮结束或初版被接纳就自动交付半成品。

按问题使用“用户固定项与可调项 → 相关游戏事实 → 会发生什么及其因果 → 当前App输入 → 实际执行证据 → 目标优化”的说明顺序。它用于减少错把参数当机制的情况，不是六道必须按顺序通过的门。已有正确输入或只是答疑时直接处理当前问题；可用[计算意图导航](../app-mechanics/authoring-guide.md)取所需格式，不要求一次读完全部规则。

1. 建立角色、配装和完整玩家操作。自主排轴以最早合法衔接为基线，按用户目标比较时序。空档要有理由，施放占用、切人和脱手命中各自计时。未知参数保持待核，候选可先编辑和保存。
2. 需要原生表示时，现有角色和动作可用 `gs_transition_phase` 的 `prepare_calculation=true` 准备，也可沿[共用输入编辑](../app-mechanics/input-editing.md)导入完整原生输入。原生输入是主要内容，白板由 App 投影。辅助拓扑用于盘点，采用其强类型执行路径时按对应合同补齐绑定。
3. 盘点每个动作和来源引起的伤害、附着、收益、能量与后台事件。把影响当前方案的事实写进实际规则或事件，检查实际执行和收益。优先使用现有的自动规则。需要补正时选能保留后继状态的[通用输入或覆盖](../app-mechanics/review/corrections.md)，同一范围由一个来源交付。
4. 用当前表示支持的组合、校验或计算查看缺项。先修影响后续判断的问题，保留正确输入和资料。改动后用新修订复核受影响的命中、元素、资源和收益。当前结果通过后，仍按[结果检查](focus/closure.md)核用户目标、时间窗和可见的优化机会。

## 遇到失败怎样继续

| 实际情况 | 接下来做什么 |
|---|---|
| 参数、路径或结构有误 | 按回执 `recovery` 的资源和指针读父级或作者字段。回执未给指针时从能力目录查。修正请求并使用当前修订。 |
| 回执有下一页或给出引用 | 沿 `next_offset`、真实资源指针或转存文件继续读所需详情。读已保存结果时用该结果的修订与身份。 |
| Q 能量或技能次数不足 | 已保存执行诊断时，沿回执 `recovery.request` 查首个失败动作和实际账目。核产球、接球、返能、冷却、溢出与继承。先补有依据的遗漏，再在已有授权内换词条或调时并重算。后续未验证动作等新执行再下结论。 |
| 任务所需机制缺输入 | 保留用户目标，按缺项补模型、初态、来源或绑定。例：动态替换缺元素规则集时，补元素依赖和实际附着，保留动态结算。 |
| 自动来源未覆盖，或当前入口没有对应能力 | 在实际公开合同中找等价通用表达，沿当前授权使用。需要近似时说明证据、影响和用户任务允许的范围。确有未解决项就保留当前候选，继续可独立完成的工作。工具未开放和资料确实缺失分别查证。 |
| 写入结果未知、修订冲突或服务故障 | 先回读当前修订和操作状态。确认未执行且可安全修复时再提交。持续外部阻断时说明已保留成果、具体阻断和恢复所需条件。 |
| 下一步确实涉及用户锁定项、现有公共事实纠错或正式应用 | 先完成已有授权内的工作，准备可审核的具体差异，再请求必要批准。初配为 Agent 自行选择且仍在可调范围内时，直接调整。 |

App 原生可从[结果检查](focus/closure.md)进入已有诊断，外部软件入口见[补正](../app-mechanics/review/corrections.md)。活动数据库知识更新遵循受控提案和发布流程。工具失败、文件权限和用户对领域操作的批准分别核对。

## 交付与续接

候选与正式白板分别保存。当前输入可保存为候选检查点或任务文件，写文件后回读；要进入当前候选，沿真实编辑或导入入口提交。需要用户选路径时可用实际文件卡，`export_candidate_input_draft` 处理已捕获的候选修订，`save_current` 保存正式文档。文件卡为 `completed` 时报告成功，旧快照标明修订。用户可在模型正常工作期间处理已捕获快照。

正式结果按当前计算接纳、精确候选审核、修订及文档基线校验和应用回执推进。草稿审核独立进行，导入草稿仅恢复输入及只读证据。遇到关键进展、取舍或阻断时给中文过程说明，最终按实际回执交代候选、已完成与未验证范围、审核、同步和文件状态。继续工作使用[上下文恢复](context-use.md)。
