# 统计截止与完整任务校验

计算前读取当前`rotation_capabilities.damage_reporting`／动作schema。`damage-report-window-v1`把统计截止与完整执行周期分开；以下方法仅用于实际提供该合同的版本。

手工 Buff 已逐次填写绝对时点时，在 `mechanics_model.manual_buff_repeat` 设 `once`。应随每个周期重放的手工窗口使用 `each_cycle`，能叠的窗口会保留实际份数。旧文件省略该字段时沿用 `each_cycle`。如果组合回执指出恰在统计截止出现额外窗口，先核实际施加次数，然后改正重复方式并按原截止重算。

- 用户指定时间：在`rotation_model.damage_report`写`contract`、`mode="explicit"`、`end=T`。T须为正、位于执行周期内。不要擅自缩短用户要求。
- 用户未指定：`mode="last_active_damage"`。按已核实的组件语义，将施放阶段直接命中的稳定ID列在`active_hit_ids`，能力直伤操作ID列在`active_operation_ids`。普通多段pattern的生成命中ID也可绑定。末次实际主动输出动作的这些命中中，最后结算时点就是T。
- 主动操作不造成伤害时，在`non_damage_action_ids`明确登记并解释。纯等待／切人不作为输出锚点。`audit_action_ids`只用于有据的额外审计操作，不能把真实任务要求的输出改标以删除分母。后台首跳不因发生在施放占用内变为主动伤害，弹道直接命中也不因晚于占用结束变为后台。
- 持续Q/E只把施放阶段直接命中用作锚点；后续后台尾伤不延长默认T。没有可靠组件／时点时补资料或询问；不要用Buff到期、最晚后台伤害或`occupation_end`猜截止。

`rotation_model.period`仍是完整输入及来源轮次的执行边界，不能为缩短DPS分母改成T。新白板默认采用自动截止；旧无此子合同输入保持原先显式period口径，重新采用新规则须fresh输入／计算，不重签旧结果。

计算窗口为`0≤t≤T`：同刻实际结算全部包括，之后后台尾伤排除。普通、星／月完整贡献组、手工伤害、单事件固定接管和外部补充共用同一谓词，不先删贡献成员再重排权重。窗口外已执行事件仍用于状态／能量审计，不计入正式总伤。按回执读取`damage_report_window`，其中包括截止依据、纳入／排除数、`required_validation`和`optional_audit`。

三件事分别汇报：伤害报告窗口是否完整，用户任务必需动作／能量是否完成，额外审计是否完成。前两项都通过才可能正式接纳；尾部可选审计失败不能伪装为必需两轮循环成功，也不追溯推翻已独立验证的有限数值。最后要求动作被拒时先修复，不能回退到上一成功动作取得更好DPS。纯免疫或指定窗口内确无伤害可以得到真实0，但没有直接锚点不等于合法零伤结果。

交付中的App、JSON和两类Excel必须同窗。界面保留完整轴供查看，截止线不是删除后续动作的操作。查看`damage_report_audit_hits`只代表窗外审计，不把其小计另加到正式总伤。改时间、主动／后台分类、来源或面板后fresh重算，保留旧代结果。
