# 动作从属面板取样

仅在当前机制capabilities提供`action-snapshot-capture-v1`、相关档案schema提供`action_capture`时使用。它记录成功动作后某个显式时点的自身收益状态，不推断游戏帧数、不生成伤害、不施加Buff或消耗次数。须有可引用的实际动作输入，不要求先进入某个focus。

资料阶段把“来源如何触发、效果何时生效、伤害按何时自身状态取样”分别记入角色或装备说明。数据库的回调关系不等于精确游戏取样时刻，旧版本测试与本次校准也不能混为事实。所需时点未知时保留问题，不用零偏移或条件事件代填。

转换时在`mechanics_model.snapshot_captures`声明`{id,action_id,offset,precision,status,source}`。每个实际动作至多一项；偏移非负、精度为正且能表示为整数微秒，取样在该动作占用内并早于输入窗口末端。ID是本地稳定引用；声明256项/128KiB与执行累计8MiB限制以当前capabilities为准。

- 手工命中/模式以`self_snapshot_event`引用对应取样ID。
- 接口支持的单接触、多通道或周期档案使用`self_sampling="action_capture"`，引擎按每个实际动作找到其唯一取样；无须Agent给每次派生命中填写ID。一个通道的取样选择不擅自改变其他通道。
- App可按既有能力填写一次校准并展开到其当前动作。明确选择关联的命中或档案，保存后仍是可检查的逐动作声明；新增动作后需再次核对完整覆盖。修改档案取样含义后重新预览和确认，不沿用旧接受指纹。

成功父动作完成pre/post处理后，取样才进入原事件队列；零偏移也不位于父动作之前。相同时间按实际order/causal检查，不靠增加极小偏移掩盖先后。取样缺失、晚于使用者、取消或前置动作未成功时不会退回当前面板或上一轮快照。首片对取样前成功切出或同角色后继动作采用保守未决处理，不宣称模拟所有取消机制。

自身取样与提供者当前属性、敌方实时状态分别处理。例如某收益要求提供者当前攻击力时，不能因为伤害使用自身快照便将该外部收益一并冻结。

计算后核对`snapshot_captures`、真实取样和引用流水以及动作/能量失败。完整计算包与仅结果导出保存独立取样证明；Excel的「面板取样」页为只读执行记录。公式仅做固定事件结构下的局部数值情景，不重新判断时序、取消、触发或次数；取样声明/引用、动作或来源变更应回App重新生成。
