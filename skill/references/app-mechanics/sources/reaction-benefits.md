# 普通扩散的装备收益来源

仅当当前 capabilities 提供 `upstream_reaction_benefit_contract` 时使用。实际 schema、支持范围和默认场景由该契约提供，不凭本文猜新增字段。此路径复用 `effect_bindings[].upstream_recipe`，不会增加新的动作或手工 Buff 时间表。

## 资料和转换

资料阶段读取角色所选套装及完整效果原文，保存到对应小文件，核对常驻已含项、触发与范围。普通冰水扩散的装备收益可由当前来源编译器自动取得常驻反应加成、敌方减抗数值与持续时间。不要把两件套风伤重复加入给定面板，也不要把同源四件套反应加成再写成手工 Buff。

动作检查点和事件拓扑完成后，使用真实装备 requirement 的 `proposed_binding`，以 capabilities 的 `default_scenario` 建立 `upstream_recipe`，`parts` 留空。当前 profile 是 `equipment-ordinary-swirl-benefits-v1`；它监听实际反应，不填写爆发 `ability_refs`。明确当前元素目标、整个窗口满足原始来源范围、开始前没有该源减抗，以及已校准的原子命中顺序；状态、依据和来源确认分别记录。未知不能填成已满足，原始 range 数值也不能在没有单位证据时随意解释成米。

先 compose，阅读 `upstream_compilations` 中本来源的完整分支、缺项、场景假设与 `required_confirmation`。只有实际条件符合时才由 Agent 接受本次综合指纹，无需让用户逐项点击授权。来源或场景变化后复核新的预览，不照抄旧 hash。确认不能将未知状态或未支持结构改为 ready；需要更改机制解释时返回event_topology修订事实与关系，再进入numeric_model转换。

生成物只属于执行副本：一项持有者常驻扩散加成，两条按冰/水分别触发和刷新的减抗规则及明确初态。不要将报告里的 `parts/rules/initial_rules` 回填原生模型，也不要复制每次扩散时间或再手写同源减抗。这些机械步骤由现有反应与收益队列完成。

## 计算核对

- 使用引擎实际输出的普通扩散事件，不能按“头上有冻结图标”手工宣称冰扩散。冰水分别计时；只有水扩散就只刷新水。同一元素刷新持续时间，不叠成两倍减抗。
- 新减抗要求持有者在场，离场后已经建立的减抗仍计时；常驻扩散加成只属于持有者，但可以作用于其后台扩散。其他角色触发不能替持有者刷新。
- 扩散成立而派生伤害被伤害ICD拦下时，仍可能刷新减抗；未命中、没有成功附着或没有可扩散元素底时不能凭动作名生成减抗。
- 现有原子顺序是父命中结算后处理反应收益，再生成原目标扩散伤害。同刻多个直伤是否属于同一真实游戏伤害包仍需校准，不能靠排序数字冒充游戏已经验证。
- 查看 `reaction_benefit_compilations`、机制流水与只读“反应收益来源”工作表。来源数值、装备、场景或事件顺序改变后回 App 重算，Excel 不重演元素和收益状态机。

## 明确边界

当前仅普通冰水原目标、固定单人给定面板、已接受冻结参考模型、无命中停滞。开始前已有减抗、空间未知、`manual_buff_repeat=once`、多提供者争用、传播及火雷/特殊反应不在本投影内。完整来源仍 `partial`，局部可执行不代表全套效果或整队游戏机制已证明。

角色天赋与此装备来源独立。提供 `passive_source_contract` 时，按[固有天赋来源](passives.md)使用 `passive_sources`；新增路径仍在联调，不扩大此装备profile的覆盖。`NONEXTRA_ELEMENT_MASTERY` 不等同任意总精通，固定相等口径、显式突破和实际父链需另行核对。天赋可后台触发的资格不能反向取消本装备动态减抗的在场要求；同一反应同时涉及两类来源也不合并确认或重复手写收益。
