# 有限次数收益来源

这是兼容入口。若运行时提供 `mechanism_source_contract` 且目录有适合当前主体及动作资格的受审资料，优先使用[通用机制来源](../execution/materialization.md)。同一收益只保留一种交付，不把本页的局部身份/变体限制推成所有机制的通则。

当运行时提供 `limited_hit_benefit_contract` 时使用本文。原生方案表示下从 `capabilities` 的 `/limited_hit_benefit_contract` 读取，独立 CLI 完整响应中在 `data.plan_contract` 下。按当前 `default_source`、schema、支持范围和可确认问题码建立输入。系统处理受审收益的数值、施加、每人次数和属性采样，仍需有证据的父动作和场景。

## 资料阶段：查询父来源并保存一次

先按[数据获取](../../data/query.md)读取角色原文及相关条件，再用 `db runtime` 的 `limited_hit_benefit_profile` 查询精确父技能。这里的 `param_index` 是**父动作的直接伤害参数**，不是有限次数收益的系数参数。由返回的完整 Talent 写入关系和父攻击身份定位收益，不能因两个参数数值相同就互换用途。

例如，当前受审申鹤长按战技的 C0、有效10级父参数查询为：

```json
{"action":"limited_hit_benefit_profile","character_id":10000063,"slot":"skill","talent_level":10,"constellation":0,"param_index":1,"version_line":"release"}
```

示例版本线须替换为本次数据库实际选择；`release` 标签不保证只含正式服内容。角色与参数身份须由资料定位，不能把示例当作通用默认。

```text
db runtime --input limited-hit-request.json --output facts/limited-hit-source.json --summary
```

把完整结果和原文留在该事实文件，在角色说明中记录路径、快照、来源指纹、父参数身份及未覆盖分支。已知的多项查询可按[运行资料契约](../../data/runtime-query.md#同快照批量与资料小文件)同批落文件，不为每次施放或每次受益命中重查。查询 `ready` 只证明这份资料投影可用；`whole_source_status=partial` 和未评估执行状态不能改写为整技能已还原。

## 数值阶段：绑定、校准并接受

先完成[动作档案](../actions/event-profiles.md)的来源与完整动作检查点和事件拓扑，使父档案就绪，再从能力默认草稿建立 `limited_hit_benefit_sources`，引用该 `action_event_profile_id`。系统从父档案取得提供者和技能身份，不另抄角色、收益系数、持续时间、次数上限或每击攻击力；原生方案也不保存服务端生成的规则。

当前局部参考仅支持一个提供者的 **C0、有效10级、受审长按战技**。它不改变总体10级／对应命座13级原则；13级、点按、混合变体或其他未支持来源仍须明确登记，不能降命座冒充原方案。此入口也不解除父攻击元信息中尚未支持的分支。

需有依据地声明普通单目标、单人固定存活队伍、施加与保留范围谓词、无既有同源效果及无外来改动，并显式选择 `zero_hitlag_reference`。这些是有限参考场景，不是引擎已模拟真实距离、死亡或卡肉。未知保持默认 `unknown/null/pending`；有依据采用的近似可用 `assumed` 并写明依据，不能只改状态来消除缺项。

`calibration` 表达动作开始到效果施加的偏移及其证据精度，按契约明确填写到微秒；零偏移是明确选择，null 是未知。精度声明不授予时间容差。App 会检查实际动作、激活与首次命中的顺序及窗口；若校准改变动作检查点或事件拓扑的含义，先回资料／排轴阶段修订。

先保持 `accepted_fingerprint=null`，compose 后查看 `limited_hit_benefit_compilations` 的完整来源、候选证书和问题。只有可确认的语义已核对且剩余问题属于契约允许的确认码时，采用该次 `required_confirmation` 并重新 compose。场景或来源仍未知时可保存草稿，但确认指纹不能把它升级为可执行。Agent 在已有任务授权内完成这项审核，无需让用户逐步骤批准。

## 执行与轴微调

施加依据成功施放，不要求初始战技命中；后续只有实际符合受审消费条件的命中才扣次数。次数按受益角色独立记录，重施在同一来源池刷新，到期失效。系统逐击读取**提供者当前攻击力**，不能改成受益者攻击力或施放时固定攻击力；读取次数和采样流水核实，勿预先手算逐击加算值。

现引擎可采样范围内的普通常量面板贡献仍参与计算。若提供者攻击力依赖命中筛选、次数约束、属性转换或其他未支持贡献，应保留 pending 和依赖原因，不能删除真实 Buff、折成匿名常数或改写来源绕过。给定面板已含常驻属性的约定不变，不再叠加装备常驻项。

必要的本轴例外仍用 `rotation_tuning.buff_hit_matches`，引用实际规则、收益和展开命中身份。匹配调整只改变收益关联：不能退还已经消耗的次数、挑高伤害命中绕开消费、越过失效时点或绕过攻击力依赖检查；同源手工收益应明确迁移，不能与自动交付叠加。更改游戏含义先回受影响阶段建立新修订。

源结构／参数、父档案语义、场景或校准改变时重新查询受影响资料并审核新的接受指纹。仅移动轴中同语义动作或增删其实际实例时，仍需重新 compose／计算验证顺序和覆盖；这些变化本身不要求重复接受未变的来源语义。

## 结果与工作簿

同时需要原生方案和两类 Excel 时，按[一次完整交付](../../outputs/app-and-excel.md)复用同次计算。查看来源回执、`limited_hit_benefit_summary`、次数消费及提供者采样流水，并核对工作簿的只读「有限次数收益」页。结果就绪不表示未覆盖命座、变体或整个队伍机制已验证。

公式工作簿保留本次执行的提供者攻击力依赖和次数／采样结果，不在表内重演这套状态机。提供者攻击力及其相关贡献、来源、动作／次数或 match 改变时，按导出 `support` 的 `regenerate_required` 回到原生方案重新计算生成；不要手改只读来源、流水或派生收益。其他参数是否可编辑以该次工作簿回执为准。
