# 生命、治疗与生命之契输入

先确认效果需要的是最大生命面板、当前生命、实际回血、耗血，还是生命之契。`stats.hp` 始终是最大生命。只计算最大生命转攻击等效果时，继续使用属性账；不要因此创建生命事件。

需要动态生命反馈时，在 `mechanics_model.health_model` 中声明角色初始生命比例、生命之契比例、生命上限变化时的处理方式，以及真实发生的事件。CLI 和原生 Agent 都从 `mechanics_capabilities` 的 `/health` 或完整机制 schema 读取当前合同。可以用原生方案编辑或 `mechanics_fragment` 提交，不需要角色专用接口。

- `heal`：按声明的基数、系数、加值和治疗修正得出治疗量，先抵扣生命之契，再恢复生命；记录实际回血与溢出。特殊效果可明确声明 `bypass_bond` 或 `allow_hp_restore`，并写出依据。
- `hp_loss`、`hp_damage`：分别声明耗血与实际受伤扣血。后者输入已经过护盾和减伤处理的数值；引擎不凭空安排敌方攻击。可显式声明最低剩余生命。
- `bond_grant`、`bond_reduce`：增加或消除生命之契；消除不自动当作回血。
- `reset_counters`：在真实技能窗口开始等时点重置累计读数，不改变当前生命或生命之契。

每条事件有稳定 ID、时点、同刻顺序和重复范围。属于某动作的事件填写 `action_id`，必须晚于该动作并使用同一重复范围。按实战逐次安排治疗／耗血，不把完整持续时间的治疗提前放在施放时。

`health_change` 可以触发既有增益／资源规则；条件表可按生命比例、生命之契或累计量设置阈值。`kind=health` 表达式可以读取 owner、recipient 或 team 的当前生命、生命比例、实际累计回血／耗血／变化比例等，并用 current、trigger、event 指定取样时点。team 是已登记生命模型角色的合计；要表示全队，必须登记全队。event 只使用本次动作所属轮次的真实取样，缺失时不会借用上一轮。

最大生命变化按显式 preserve_fraction／preserve_amount 同步；该同步不计为治疗或耗血。当前生命反过来影响最大生命时，需要 trigger 或 event 取样切断反馈，不能要求引擎无限迭代自我增幅。此接口不模拟死亡后的复苏、敌方 AI、护盾碰撞或随机受击。

生命归零后，死亡、离场及召唤物后继行为属于尚未实现的范围，计算保留失败前记录并报告待补能力，不会把角色当作仍然存活继续计算。累计量按角色保存；`reset_counters` 同时重置该角色的所有生命累计量。多个不同窗口的机制需要分别设计取样，不要让一个窗口的重置冒充另一个窗口的统计。

计算后检查 `result.health_ledger`：每条事件应能看见处理前后生命、生命之契、实际变化、溢出及来源。再检查实际伤害消费到的增益。程序接纳只说明声明的输入可执行，不证明角色治疗频率、生命之契规则或所有技能都已完整录入。
