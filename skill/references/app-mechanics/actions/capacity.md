# 受审技能最大次数来源

仅当当前 `capabilities` 提供容量目录、容量来源与消费账合同时使用。本参考处理元素战技共享次数池，不按角色写特殊规则。

## 先确认边界

- **最大次数不是冷却。** 最大次数只决定资源池上限；`cooldown.duration/start/recovery` 决定恢复时点。
- **最大次数不是全轴施放上限。** 只要冷却恢复，完整动作轴内可以继续施放。
- **目录不是执行来源。** 目录只给 `model_ref`、精确目标、审核和条件匹配状态，不给容量值，也不证明材料、适用性或执行权。
- **模型不补动作。** Agent仍须在动作输入中明确每次实际施放；模型也不补伤害、产球、附着或 Buff。
- **当前主库可能没有资料。** `release`/`beta` 目录为空时如实登记缺口，不手填一个“看起来正确”的模型引用。

## 工作步骤

1. 在资料阶段先保存角色成长、武器、圣遗物、队伍和相关战技身份。明确角色等级、突破、命座、战技基级、武器 ID/等级/精炼、五槽存在状态和版本线；未知字段保持未知。
2. 把同一角色、同一冷却组、共用次数池的全部元素战技动作列全，明确动作变体；这些是动作和资源的实际输入，不是进入特定focus的要求。目录查询不能代替动作规划。
3. 从 App 容量目录读取 `view=all` 的完整稳定分页。只在“已审核 · 完全匹配”或“已审核 · 部分匹配”中选择；部分匹配的未知字段仍需复核。不要从待审核、已撤销、合同无效、尚未评估或不匹配组复制引用。
4. 保存目录给出的 `model_ref={id,revision}` 与精确 `target`。保留原始 ID 和修订；不要抄目录显示名作为机器身份，不要从目录抄容量数值。
5. 白板 `capacity_intents[].context` 默认为 `null`。只有用户在界面明确点击普通开放世界预设，才使用 `ordinary_open_world / external_capacity_effects=none / window_changes=none`。Agent 不静默写入或传播预设。多项意图的非空场景必须完全一致；`null` 与非空混合保持待处理，等待用户明确应用到全部或清除。
6. 分开填写冷却与开场状态：
   - 所有共池能力使用同一非空 `cooldown.group`；
   - 明确 `duration`、`start=action_start|occupation_end`、`recovery=sequential|parallel`；
   - `initial_ready_in=[]` 表示开场全部可用；`null` 表示未知；非空数组保存每个尚未恢复次数的剩余秒数并按升序排列。
7. 检查能力集合完整且排他：同池本地能力没有遗漏，一个能力不属于两个容量来源；容量来源已经拥有 `cooldown.charges` 时，不再让旧动作资源来源或手填字段重复拥有该值。
8. 按 **fresh compose → review → confirm → fresh apply** 执行：
   - 第一次 compose 读取完整模型、激活增量、竞争库存和实际选择；
   - 核对容量、来源、适用域、冷却与开场队列；
   - 只复制本次预览的确认指纹；
   - 应用前再次 compose；新鲜指纹、状态或方案变化时重新审核，不能沿用旧确认。
9. 计算后检查 `action_capacity_compilations` 和 `rotation_check.action_capacity_consumption`：每个来源须 `ready`，每个声明动作须有提交/拒绝或明确的未检查、未提交、未验证记录；核对消费前后次数、恢复队列、下一恢复时点、未报告数和提前终止。
10. 白板回传再做一一闭环：意图动作 → 原生动作 → 同角色战技能力 → 唯一容量来源 → 唯一 ready 编译 → 实际消费回执/账本；不得多出未声明来源，也不得用目录记录替代执行账。

## 白板最小意图

```json
{
  "id": "capacity.intent.1",
  "actor": "actor.id",
  "action_ids": ["action.e.1"],
  "version_line": "release",
  "model_ref": {"id": "reviewed.model.id", "revision": 1},
  "target": {
    "character_id": 10000000,
    "skill_depot_id": 100,
    "skill_id": 1000,
    "variant": "tap"
  },
  "cooldown": null,
  "initial_ready_in": null,
  "context": null
}
```

这个形状可以保存为待补白板，不能视作可执行来源。目录选中只替换 `model_ref` 与 `target`；修改场景语义、动作集合或实际配置后，旧预览和确认都应作废。

## 无容量资料的兼容路径

旧白板 v1 或 v2 `capacity_intents=[]` 继续走原有计算流程，不添加容量来源、场景、编译或消费账。不要为了“升级格式”生成空来源或虚假消费记录。只有非空意图才要求上述闭环。

## 当前限制

当前静态合同只覆盖已审点按战技资料及其精确适用域，不覆盖动态冷却/容量变化、窗口内换装或状态重置。正式主库当前两条资料线均没有容量事实，beta 数据也不可用。外部信任根问题延期；不能宣称内部指纹能够识别整份方案和交付包被一起替换的情况。
