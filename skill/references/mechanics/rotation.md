# 排轴原理：Buff 时序、循环结构与快照

> 适用：循环 DPS 计算、Buff 覆盖率估算、排轴方案设计与评审。
> 排轴操作流程见 [动作与来源核对](../workflow/coverage-and-review.md)。本页说明计时、增益与能量原则；数值计算成功不自动证明动作或循环可执行。

## 一、基本概念

- **循环（Rotation）**：队伍四人按顺序施放技能、切人输出的一个完整周期，之后重复。
- **轴（Timeline）**：以秒为单位的循环时间线，标注每个动作的起止与每个 Buff 的覆盖区间。
- **循环 DPS**：`循环总伤 / 循环时长`。**时长与伤害同等重要**——压缩循环长度和堆伤害是两条并行的优化路径。
- **本项目报告截止**：用户指定时间优先；否则取末次主动动作施放阶段的最后直接命中。按同窗总伤除以截止秒数，后续后台尾伤／Buff存续不延长分母；执行／能量检查周期单独保留，不因此改来源轮次。接口见[统计窗口](../app-mechanics/review/report-window.md)。
- **站场 / 后台**：玩家施放占用与效果存续分别计时。脱手效果的施放仍占动作；符合条件的后续伤害可以在角色继续操作或离场后结算，不把最后一跳当强制占用结束，也不把施放写成0秒。

## 二、循环时长的构成

每个动作的耗时构成循环长度，拉表必须计时的动作：

| 动作 | 典型耗时（估算） |
|---|---|
| 元素战技（E） | 0.5–1.5s（视动作前摇/后摇） |
| 元素爆发（Q） | 1.5–2.5s（含动画，部分角色动画期间可切人取消部分后摇——需逐角色确认） |
| 普攻连段 | 一套约 1.5–2.5s |
| 重击 | 约 1–2s（含蓄力/动作） |
| 切人 | 分别核对上个动作可取消时点、两次切换的最短间隔和实际操作延迟 |
| 冲刺/跳跃取消后摇 | 节省后摇但消耗时间本身，净收益视技能 |

> 以上只用于理解耗时量级，不是统一排轴间隔。具体角色动作时长需以实测或附录为准，不能照表填固定间距；时长误差直接影响DPS。

自主排轴优先做到紧凑，并以用户目标优化。默认目标为 DPS，用户给出其他目标或固定安排时依其要求。先按施放占用、允许取消点、切人限制、冷却和资源求最早合法衔接。检查参考轴的留白，删除无收益缓冲，后台伤害按自身时序继续。

切人时点和下一次攻击的开始、命中分别安排。比如队友需等后台挂元素才出手，可比较先切入再等待与原角色继续驻场，核两种安排下的收球、前台收益和反应。如果用户只要求一组内至少触发一次，按该条件核对各组。若延迟接球、等底或对齐增益能改善整体目标，保留该等待并说明条件及比较结果。

改时后重算受影响的后续事件、资源、附着与收益，用相同任务要求和统计口径比较。主动采用已有证据支持的改进，注明实际比较范围及仍待查证的时序。未知占用保留待核，取消点以资料为依据。

## 三、Buff 覆盖率

```
时长覆盖率 = 循环内 Buff 生效时长 / 循环时长
```

- Buff 从其机制规定的**实际触发/生效时刻**起算；按下、成功施放、命中、反应和切人不是同一时点。
- 持续型 Buff（如 12s 增伤）排轴时要画出覆盖区间，确认主输出窗口是否完整落入。
- 原文单次时长、每次有效触发与最终覆盖分别记录。可刷新但不可叠加的效果合并覆盖，不能将重叠窗口加算，也不能把连续覆盖时长改成单次时长。
- **覆盖率加权法**（粗算）：`平均伤害 = (1-p)*无Buff伤害+p*有Buff伤害`，增益贡献为`p*(有Buff伤害-无Buff伤害)`。p应按输出命中/伤害分布确定；只有输出均匀时，才可用时长覆盖率近似。精确做法是按Buff有无分段计算，不把总伤害直接乘覆盖率。时长覆盖、命中覆盖与伤害贡献分别衡量，不能混用；[App结果口径](../app-mechanics/review/results.md)单独维护。
- 多个 Buff 错峰与对齐：把高价值 Buff 对齐主 C 爆发窗口是排轴的核心技巧；拉表要检验的是对齐后各 Buff 的覆盖是否如预期。

## 四、快照机制（Snapshot）

- **快照**：某个组件的指定属性/收益在有据时点取样，后续使用该值；采样对象、时点和适用范围分别核实。不能从一次属性快照推出所有Buff、反应精通或敌方状态也被冻结。
- **非快照（动态）**：实时按当前面板结算，Buff 掉了伤害立刻降。
- **哪些属性在何时快照是逐技能机制**，先查原文和数据库 annotation；未记载则外查或待核实，不从“持续脱手”直接推定快照。
- Buff 也可快照相关：部分 Buff 标注"施放时锁定"（如部分武器/圣遗物效果），其加成可被快照进脱手技。
- 排轴应用：快照技能的施放时机要安排在 Buff 峰值之后；非快照技能则更依赖 Buff 的全程覆盖。
- 自身属性快照与敌方动态状态分开；每项属性按实际组件规定的时点取样，不把敌方抗性、反应或他人当前属性随整面板一起锁定。软件表达方式见[取样适配](../app-mechanics/execution/attributes-and-sampling.md)。

## 五、能量循环（充能约束）

粒球按每位接收者的元素关系、前后台和ER分别入账；直接回能与粒球的来源、基础量和入账算法分开记录，不能互相冒充。ER比率`1=100%`。普通/重击可能触发的直接回能也不是元素微粒，不能默认每次动作稳定提供。粒球基数参考：[KQM能量机制](https://library.keqingmains.com/combat-mechanics/energy)，核对于2026-09-13。本项目当前直接回能计算口径单独见[资源适配](../app-mechanics/execution/resources-and-lifecycle.md)，不将项目政策冒称外部资料已经证实的游戏事实。

| 入账基数（前台，ER=100%） | 同元素 | 异元素 | 无元素 |
|---|---:|---:|---:|
| 每个微粒 | 3 | 1 | 2 |
| 每个晶球 | 9 | 3 | 6 |

后台在上述基数上乘队伍人数系数：二人 0.8、三人 0.7、四人 0.6；人数越多，后台折扣越重。再乘各接收角色自身 ER，不能使用产球者的 ER。

执行时分开记录技能/武器/共鸣触发、粒球生成、实际能量入账、固定回能及爆发扣能。技能重置本身不是产球；追加 E 是否施放并命中需另有动作。武器与共鸣的条件/CD 按当前原文及机制核实，不凭名称自动生成能量。怪物掉落只按已声明的数量、元素、粒/球和时间安排；未提供不暗补。

判断前台使用**能量实际入账时点**，不使用视觉吸球时点；来源依据见 [KQM 能量入账证据](https://library.keqingmains.com/evidence/combat-mechanics/energy)。先接球后扣能可能溢出，先扣能后接球可留下能量，因此同一轮总量相同仍可能有不同结论。

ER粗估先按采用的结算口径区分随ER缩放的基础收入与不随ER变化的输入，不能一概把固定数值回能当成可直接从消耗中扣除的独立常数。粗估仅供试配；每次Q前余额、溢出、初态、到账延迟、临时ER与跨轮状态仍须复核。在既定来源和触发安排下，没有任何随ER缩放的有效收入时，提高ER不能解决缺口；不能仅凭没有粒球收入作此判断。合法改时或等待后重新核验，不删失败爆发、不重置续轮满能量，也不借未声明收入宣称通过。

首轮满能量不能当作每轮输入。续轮继承余额、CD/充能次数和在途粒球。用户没有指定产球情景时，按有依据的分支概率计算每次合格产球机会的平均数量，包含零粒分支。明确指定最低、最高或实测数量时按该情景执行。触发条件和冷却仍按实际机制处理，已经按成功处理的武器触发无需再乘成功概率。说明平均产球下的能量结论；若循环需要稳定性保证，另查低产球情景。

## 六、排轴设计要点（评审一份轴时看什么）

1. **循环是否闭合**：动作占用、逐次能量和 CD/充能次数均自洽；同技能起算点、变体共享 CD、重置条件与跨轮状态须明确。
2. **Buff 对齐**：主输出窗口是否被关键 Buff（增伤/减抗/攻击拐）覆盖。
3. **反应安排**：附着顺序是否让高面板者触发高倍率反应（见 reactions.md）。
4. **快照利用**：快照技能是否吃到了峰值面板。
5. **切人衔接**：逐处核对切出许可、相邻切换间隔、实际输入延迟与下一动作，按实际占用和重叠关系计时。
6. **容错**：实战中断（闪避、被打飞）对轴的破坏程度；纸面完美轴与可执行轴要区分说明。

## 七、循环总伤的拉表方法（软件引擎与 Excel 近似的共同框架）

```
循环总伤 = Σ(每个动作段的伤害)
动作段伤害 = 该段命中数 × 单跳伤害（代入该时刻生效的乘区）
```

- Excel 粗算：按"Buff 覆盖率打折 + 主要输出段"估算，明示简化。
- 精算：按每段实际状态、命中和取样分别计算，数值成功不证明动作、元素或循环已可执行。具体软件范围见[结果说明](../app-mechanics/review/results.md)。
- 报告口径：总伤 + 时长 + DPS + 关键假设（命中率、触发次数、ER 自洽性）。

## 八、快速检查清单

1. 循环时长里有没有漏算动作/切人耗时？
2. 关键 Buff 的实际覆盖区间画出来了吗？
3. 快照技能的施放点在 Buff 峰值之后吗？
4. 能量账：每次 Q 前是否足额，固定回能、ER、前后台、溢出和续轮继承是否分别处理？
5. CD 账：技能间隔、起算时点、充能次数及重置条件是否成立？
6. 该轴在实战中可执行吗（要不要在结果里注明操作要求）？

## 附录：帧率对排轴的影响（附录级参考）

帧率是精细情景变量，需有对应资料才能换算；不能仅凭FPS数值把所有动作统一缩放。

帧率（FPS）会影响游戏的多个环节，进而影响实际排轴与理论计算的一致性：

| 影响环节 | 说明 |
|---|---|
| 切人 | 切人动作与切人 CD 的判定以帧为粒度；低帧率下切人响应变慢、最短切换间隔的实际耗时增加 |
| 附着 | 元素附着的判定与 ICD 计时以帧为节拍；帧率波动会影响附着的实际命中节奏与 ICD 重置时机 |
| 技能频率 | 单位时间内的技能/攻击判定帧数受帧率影响；部分按帧结算的持续技能（DoT、雷暴云类）的实际跳数与帧率相关 |
| 帧生成时间 | 动作前摇/后摇以帧为单位，帧率变化直接改变动作的实际耗时 |

排轴层面的推论：

- 理论轴（按理想帧排布）在低帧率下执行时，循环时长会被拉长、Buff 覆盖窗口可能发生错位——报告的循环 DPS 是相对理想帧的上限。
- 部分依赖帧判定的技巧（特定取消时机、卡帧附着）在低帧率下不可复现；涉及此类技巧的轴应标注帧率前提。
- 某些具体机制可能对帧率敏感，须有对应版本/机制实测；不能把未附证据的FPS数值当已核事实。此项默认不纳入，按任务需要研究。

是否研究帧率取决于任务要求；报告说明采用的时序情景及证据。
