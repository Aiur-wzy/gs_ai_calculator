# 帧率、现实秒数与战斗计时

做快帧或慢帧估算时，先从[动作估时指南](action-timing.md)取得原始时点，再区分这个时点来自技能计时器、动作动画、命中停顿、输入衔接还是切换延迟。把确有依据的变化写入对应事件，重新检查命中、附着、Buff 和能量。常规 App 方案的极星辉域仍按标称 4 秒结算。开发版的显式 `experimental_384f` 使用 3.340596 秒，是固定实验输入。使用方式见[特殊反应输入说明](../app-mechanics/elements/special-reactions.md)。

## 怎样换算

以下算法只用于有证据支持逐帧取整的计时器。把第 i 帧的真实耗时记为 dᵢ 毫秒，按研究模型取最近的整数毫秒 qᵢ。实际游戏计时流速为 **Σqᵢ／Σdᵢ**，例如 1.20 表示现实 1 秒推进标称 1.20 秒。稳定帧率可用实际 FPS 算 d=1000／FPS。看单次事件落在哪一帧时，要找到累计 qᵢ 首次达到阈值的那一帧。若计时器保留越过阈值的余量，后续间隔也会变化。仅有平均帧率时，不能从它恢复跨取整边界的抖动。

- 理想实际 60 FPS 下，每帧约 16.667 ms，推进 17 ms。4 秒阈值在第 236 帧跨过，约为 3.933 秒。长时间平均的换算值为 3.922 秒。此处是取整模型演算，App 常规的 4 秒依合同使用。
- 交替出现 2.49 与 2.51 ms 时，每对帧推进 2+3 ms，真实也历时 5 ms，流速为 1。只取平均 2.50 ms 再统一取整会得出另一种结果。正好半毫秒时采用哪侧，需有计时器证据。
- 以标称秒数为基准时，乘现实用时系数 Σdᵢ／Σqᵢ；以同一计时器的旧帧率实测为基准时，乘新旧用时系数之比。旧 384 实验对部分动画也使用了相对 60 的比值，属于实验假设。

## 逐计时器查证

| 对象 | 已有证据及下一步 |

| 极星辉域结算间隔 | 研究的 Stellar-Conduct 小节列有快／慢档对照，见下表。创建即时增益、刷新后的相位和层数到期应各自测量。引擎显式实验档对结算和对应层数有效期使用固定间隔。 |
| 米提亚信标、奥黛塔后台 E | 研究的 Mitya 小节报告信标 384 档约 1.25 秒，接近标称 1.5×0.835149；后台技能小节列奥黛塔 E 频率受影响。分别核首跳、间隔、重施和末跳。仅凭后续周期无法认定首跳也同倍率。 |
| 星扩散风旋爆发 | 研究在 Stellar-Swirl 小节指出爆发等待受影响。风旋间生成时距仍列为疑问，两者分开记录。 |

| 解封、米提亚炉心、达妮卡协同 | 历史轴按相似计时器估算。需要对应形态、触发和逐事件证据，当前待核。 |
| 技能冷却、附着组、Buff 持续、飞球、切换 | 历史轴沿用原时长。另查技能冷却、检查触发时点、附着计数与计时器。研究中存在特例，例如同一技能的冷却和后台跳数可走不同计时逻辑。 |
