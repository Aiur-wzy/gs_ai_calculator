# Excel 模式拉表指南

Excel有两条路径：已有原生方案时优先用软件同源活公式导出；简单独立分析或软件不具备所需能力时由Skill制作近似表。二者都保留可调输入和可见计算，禁用宏；CSV只用于纯数据，不冒充活公式表。

涉及完整排轴时按[工作重点](../workflow/index.md)记录动作与事件拓扑，闭合数值后生成工作簿；导出须对应同一输入修订。独立单次计算不必额外创建完整轴。扰动验证使用副本或内存修改并恢复；实际改轴或改变假设需修订受影响输入并重新计算，不要求机械退阶段。

## 原生方案的同源活公式导出

同时交付App和两类Excel，且运行时提供equipment deliver时，优先[一次完整交付](app-and-excel.md)：同一fresh结果生成原生、历史计算包、结果Excel和公式Excel。下面workbook保留为单独公式导出及旧版本路径；无需为已有完整交付再重算两遍。

运行时存在该命令时使用：

```text
equipment workbook --plan plan.json --output formula.xlsx
```

命令重新组合并计算同一原生方案，再生成公式工作簿；不要求Agent逐命中重写已经支持的公式。回执包含result_receipt和support；记录plan_id/revision与输入/输出指纹。默认给定面板已含常驻两件套，工作簿不反拆五件主副词条，也不重复叠武器成长。

| 工作簿内修改 | 当前支持边界 |
|---|---|
| 命中倍率、敌方数值 | 按实际公式重算，保留既有事件结构 |
| 角色面板、收益数值、声明属性表达式 | 仅support.editable明确列出该字段/路径且其policy允许时支持；fixed或regenerate路径不可直接编辑，不能只凭没有limitation判断，属性表达式使用固定的采样事件与依赖；partial时按具体字段要求重新生成 |
| 元素充能效率 | 使原循环检查结论失效，需回软件重查 |
| 动作/命中数/时间、规则/match/受益目标/层数/次数、角色等级、装备 | 重新执行引擎并生成，不沿用旧事件与trace |
| 回写App | 不支持；Excel编辑是工作簿局部情景 |

当前模板覆盖classic/transformative/lunar/stellar数值路径，是否能编辑还取决于该方案的依赖；不能把status=partial说成全部可改。v3完整输入窗口的已执行伤害与附加循环验证分开说明，窗口可以显式包含多个游戏轮。旧 `equipment export --format xlsx` 是结果快照，与此命令区分。

当前来源页提供摘要、稳定ID及SHA256索引，完整来源JSON在独立审计页按块保留，可离线拼接校验，不再逐行展开缩进；没有外部Excel公式链接。参数旁的实际policy决定可否编辑，不由工作簿整体partial状态一刀锁死。允许的改算属于Excel派生测算，不能沿用原accepted身份；结构、取样、权重或来源变化仍回App。输出支持新[统计窗口](../app-mechanics/review/report-window.md)时，表中总伤与DPS使用同一T，窗口外审计事件不参与求和。

打开文件检查公式、中文名称、来源与范围；挑一个support允许且实际影响伤害的数值扰动、重算、观察并恢复。动作/次数结构变化必须提示重新执行，不能拿旧trace按总伤比例缩放。数值一致性按同源事件与公式检查；不以人工表的总DPS接近作为验证。

以下各节适用于**独立手工Excel**或确有必要的自定义分析，不要求复制生成器已有计算。该路径注明“粗粒度估算，不追游戏内舍入细节”。

## 1. 铁律

1. **三区块结构**：参数区 → 计算区 → 结果区，顺序不可逆。
2. **过程透明**：计算区每步乘区一个单元格，公式直接引用参数区单元格；禁止把多个乘区压进一条长公式（用户要能逐格审计）。
3. **常量入参数区**：防御系数基数、精通公式系数、抗性分段点等写在参数区（标注「一般勿动」），不硬编码进公式。
4. **可改单元格醒目**：参数区中用户可调项（面板、词条数、Buff 值）统一填色标注。
5. **结果区必附精度声明**：固定文案「本表为粗粒度估算，不追游戏内舍入细节；实际伤害受帧率、附着时机、怪物状态波动影响」。

## 2. 公式权威与映射

**公式唯一权威是 `references/mechanics/damage-formula.md`**（乘区定义、系数、分段规则以它为准，本文不复制公式本体）。Excel 落地只做三步映射：

1. **乘区 → 单元格**：每个乘区一个单元格，标签写在左邻格。链序：
   `基础区 → 增伤区 → 暴击期望 → 防御区 → 抗性区 → (增幅反应区) → 期望伤害`
2. **分段函数 → IF**：如抗性区 `=IF(res<0, 1-res/2, IF(res<0.75, 1-res, 1/(1+4*res)))`（res 引用参数区单元格）。
3. **体系分支**：传统直伤 / 剧变 / 月曜 / 星烁乘区结构不同（月曜星烁不吃传统增伤、无视防御、精通区系数不同——见 damage-formula.md），先确认伤害体系再搭链，不要把直伤链套到反应伤害上。

**数据来源**：当前初始面板由用户/题面给定，倍率、武器/套装原文及相关技能走数据库（data-access.md）。倍率按 [拉表原则](../../SKILL.md#拉表原则) 默认10级，仅对已激活对应加级命座的技能使用13级，在参数区保留有效等级和命座依据。参数区与原生 panel 方案共用给定面板、武器/套装类型和件数，记录已含两件套等常驻属性，条件 Buff 另列，不重复加入武器成长或常驻加成。无需反拆五件主副词条；涉及明确增量的收益分析时才读 `mechanics/artifacts.md`，App自动选主属性／分配副词条仍属未来D19；用户明确指定主词条和有效词条预算时，Agent可为该任务查询基础／成长并手工构造面板，保留预算与计算依据。

## 3. annotation → 公式调整路径

追加描述（计算前必查，见 data-access.md §3）中的隐藏机制在构建时转化为结构改动：

| annotation 机制 | Excel 落地 |
|---|---|
| ICD / 附着计数 | 将触发反应和未触发反应的命中分行求和；同倍率同条件的增幅反应可用 `p=触发次数/总命中次数`，平均反应区为 `(1-p)+p*反应乘区`（p在参数区可调）。剧变是额外反应事件，按实际触发次数另计 |
| 快照 | Buff 值在参数区分「快照时 Buff / 常驻 Buff」两行，公式引用对应行 |
| 乘区归属（某加成属增伤区还是基础区） | 决定该参数进入哪个乘区单元格——归错区是最常见错误 |

自检：2倍增幅反应、p=0/0.5/1时，平均反应乘区应为1/1.5/2；不同倍率的命中不可只按次数平均，应逐段加权。Buff 覆盖也应保留无Buff部分：`(1-p)*无Buff伤害+p*有Buff伤害`。时长覆盖只有在输出均匀时可近似作为p，不能把整段伤害直接乘覆盖率。

## 4. 场景模板蓝图

模板是**起始点**，按需求裁剪扩展；下列布局为惯例非死规定。图表默认不画；仅对比类结果（武器/配装/词条梯度）可配一张柱状图辅助阅读。

### 4.1 单技能期望伤害
- 参数区：主属性（攻击力等）、倍率、增伤、暴击率/暴伤、（增幅反应：精通）、敌人等级、减防、抗性
- 计算区：标准链七格
- 结果区：不暴击 / 暴击 / 期望 三个数

### 4.2 词条收益梯度
- 参数区：当前面板 + 「单词条增量」行（攻%/暴率/暴伤/精通等，档位值见 artifacts.md 副词条表）
- 计算区：基准期望一列；每个候选词条各加一档重算一列
- 结果区：**每词条提升百分比排序表**（梯度结论）

### 4.3 武器对比
- 参数区：按武器横向多列——用户/题面为各列给定的面板、被动及条件效果（特效覆盖率假设写进参数区并声明）；固定面板相同时只比较该面板下的被动效果，不自动加武器成长
- 计算区：每列独立走一遍标准链
- 结果区：对比表 + 相对提升 %

### 4.4 配装对比
- 同 4.3，按套装类型/件数分列，保留各列给定面板及已含常驻属性，条件效果另计；固定面板相同时说明比较仅覆盖该面板下的套装效果，不反推或自动构造等量主副词条

### 4.5 循环总伤（简化轴）
- 参数区：每个技能的倍率、单循环释放次数、Buff 覆盖率（0~1）
- 计算区：`每技能期望 × 次数 × Buff 覆盖加权`，逐行求和
- 结果区：循环总伤 + 秒均 DPS（循环时长入参数区）
- 注意：这是简化轴；精细排轴先走软件的实际支持能力（software-manual.md），再按同一动作/命中数据制作需要的活公式表。逐角色列出已含/未含伤害，动作、增益和能量账见 [rotation-audit.md](../workflow/coverage-and-review.md)，不把局部表当全队结果。

## 5. 校验

交付前自检：

- 数值检查：APP与Excel按项目自身的同一输入核对单事件、乘区和汇总范围。人工表只作局部横向参考，说明等级、装备、场景与覆盖差异；无需把项目降到人工表的9级或复刻配装/轴，也不要求每次归一化人工表后才能评审。不以人工总DPS作标准答案，不设统一5–10%通过线。独立实验中Agent可以查询并采用社区表、实战答案和相似结果来改善方案，同时保留来源、适用条件、采用位置及App复算／外部补充记录；只有明确标为历史封存答案隔离的题面继续使用旧限制。
- 结构检查：公式无硬编码数值（常量都在参数区）、无循环引用。改一个会影响伤害的倍率/次数或面板输入，读取重算后结果并恢复，保留记录；标题写“可改”或公式只是硬编码总伤的比例缩放不构成完整拉表。
- 同源检查：同时交付 APP 时核对给定面板、武器/套装及已含/条件效果、角色/命中数量、时长和假设；两边覆盖不同则明确范围。固定面板＋套装选择不要求五槽，静态结果导出与活公式模板分别标注。

## 6. 交付清单

1. `.xlsx` 文件路径（参数区可改格已标色）
2. 文字解读：关键数字（期望伤害/梯度结论/对比结论）、假设声明（覆盖率、触发次数等）、精度声明

## 排轴技巧

- **循环总伤估算** → Excel 模式用「技能期望 × 次数 × Buff 覆盖率加权」简化轴（excel-mode.md §4.5） → 覆盖率的假设必须写进参数区并在交付时声明，否则结果无法复核。
- **精细排轴需求**（Buff 时序对齐、切人窗口、附着帧）→ 直接走软件引擎，不要在 Excel 里硬模拟 → Excel 模式定位是粗粒度，硬模拟既不准也误导用户。


## Excel 模式技巧

- **Buff/加成归类拿不准** → 先读技能原文及角色聚合内相关对象的 annotation，再对照 mechanics/damage-formula.md → 受益对象、基础属性与生效条件不能仅由倍率标签或机器乘区标签推出。
- **新机制知识要复用** → 在会话研究记录/获准的文件中形成带来源、版本、适用条件和未知项的库外提案；由维护流程审核、用户批准后进入隔离候选并发布完整新DB → 活动库不可写，旧annotation POST/import/review入口已停用；App普通Agent不因查明事实而取得公共库写权。
