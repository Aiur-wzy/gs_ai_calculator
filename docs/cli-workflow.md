# 推荐工作流：CLI 计算，GUI 审核

当前推荐使用 GPT-6.1 Sol 或能力更强、能够执行本地命令的 Agent。应用内原生 Agent 与 DeepSeek 的复杂任务表现仍不稳定，暂不作为主要计算入口。GUI 适合打开原生方案、查看时间轴、人工审核和找问题。

## 1. 准备独立工作目录

每次任务保存题面、查询依据、输入方案、计算输出和检查记录。给 Agent 本版 `skill/SKILL.md` 的位置、实际 CLI 入口和工作目录。数据库保持原发行内容，任务修改写在自己的方案中。

CLI 是本地计算工具，不是模型客户端。外部 Agent 负责理解任务、查询和填写输入；普通查询和计算命令不会自行调用付费模型。

## 2. 核对正在使用的版本

对外发布版优先使用随包提供的 `GenshinCalc.exe`。从安装目录打开 PowerShell。若通过小安装器安装，程序在 `%LOCALAPPDATA%\GenshinCalcStable\app`。若使用独立 ZIP，进入解压后的程序目录。先完成[数据库安装](install.md)，再查询本版入口：

```powershell
.\GenshinCalc.exe capabilities --command "equipment calc"
.\GenshinCalc.exe db status
.\GenshinCalc.exe system check-update
```

App 和数据库的当前发行标识可从更新状态中核对。本版首发应识别为 **`app-0.46.0-r19`** 和 **`db-7.2.50-r6`**。`capabilities` 描述工具能力，`db status` 显示所用资料，`system check-update` 会尝试联系已配置的正式更新入口。使用已校验且已装好的应用和数据进行普通计算时，可离线运行。

将相同版本的 `skill/SKILL.md` 和 CLI 入口交给 Agent。正式 EXE 默认读取 `%LOCALAPPDATA%\GenshinCalcStable\data`。如需选择另一个已经受验的数据目录，把 `--data-dir` 放在子命令前。源码命令用于开发和构建，实际计算仍须通过该运行环境的版本和数据库校验。详见[构建说明](build.md)。

## 3. 查询、编排和计算

任务条件应包括队伍和配装、允许优化的范围、目标轮数或截止时间，以及要交付什么。将 [Skill](../skill/SKILL.md) 交给 Agent，后续按实际问题读取资料。无需在题面中硬编码一套过时的工具调用顺序。

工具参数以本版 `capabilities` 的返回为准。[软件入口](../skill/references/runtime/software-entrypoints.md)说明普通 CLI、持久 CLI 和应用内候选的区别。连续查询或迭代时，可以让 Agent 使用持久 CLI 复用同一进程，减少重复启动与数据库校验；能力查询和启动方式也在该文件中。

操作应形成“修改输入、计算、检查执行结果、修正并重算”的循环。游戏资料或输入不完整时，应说明还缺什么。计算程序接受了输入，并不证明模型已经考虑所有技能、命座、武器效果或资源来源。

## 4. 保存正确的交付文件

请 Agent 最少交付：

- **原生方案**，用于继续修改和在 GUI 打开。
- **计算包或对应结果文件**，保存引擎输出和检查依据，不能拿手工编辑的结果替代重算。
- **简短说明**，先讲是否算完、哪些地方仍有出入、有哪些近似以及用户下一步做什么。

只需要 App 方案时不必生成 Excel。具体保存、交付及各文件角色见[同源交付](../skill/references/outputs/app-and-excel.md)。文件名由实际任务决定，不能只凭 `final`、`accepted` 等名称判断结果有效。

## 5. 在 GUI 中人工审核

打开原生方案，查看动作顺序、无理由等待、Buff 覆盖、每段伤害、资源和能量情况。结合计算报告检查结果是否完整，以及哪些游戏机制使用了近似。GUI 加载文件与运行计算是两步，单纯打开不会自动获得新的计算结果。

发现遗漏时，把具体角色、动作、时点和现象反馈给 Agent，由它修改原生输入并重新计算。最后再次打开修改后的文件核对。当前路径不依赖应用内 Agent 替你完成全部任务，也不要求为了导入独立 CLI 方案先建立原生对话。
