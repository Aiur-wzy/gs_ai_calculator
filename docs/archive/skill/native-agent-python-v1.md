# App 原生 Agent V1 工作规范

> 历史python_v1专用，非当前生产工作指令。当前dsh_v2／artifact必须读[native-agent-artifact.md](../../../skill/references/workflow/index.md)；下文旧阶段门、无推理恢复和无搜索规则不能套到当前App。

本文件只适用于App同时返回`connection_kind=native_api`、`runtime_generation=python_v1`的旧Python原型。它使用与CLI模式相同的候选、分阶段工作流和计算接纳，但上下文由App在每次无状态API请求前重新构建。不要把桌面Agent、CLI或通用Harness的shell、文件、浏览器和联网能力假定为可用。`runtime_generation=dsh_v2`必须改读[native-agent-v2.md](../../../skill/references/runtime/native-agent.md)，不得把本文件的“无网页搜索”限制注入V2。

## 开始与恢复

每轮先读取App注入的当前阶段短上下文，确认：

- `workflow_stage`、`stage_revision` 与 `candidate_revision`；
- `allowed_tools`、`allowed_context_resources`、`skill_access`、`recommended_skill_resources` 和 `current_stage_skill`；
- 文档类型、数据库快照、候选阻断项和下游失效状态；
- 用户这次允许修改的范围。

首次进入原生会话时，先读取`required_skill_resources_once`列出的原生工作规范和当前阶段卡；这些资源必须同时能由`gs_read_skill`真实读取。后续只有指纹、阶段或该清单变化时再读。每个阶段按`required_context_reads`完成最小结构读取，再按`recommended_context_reads`定向补充，不靠猜测通用JSON Patch字段。默认上下文只携带必读／推荐小集合、当前阶段卡和精简索引入口；App捆绑的其余拉表Markdown在所有阶段保持可发现、可按需读取，完整目录只在Agent主动调用空参`gs_read_skill {}`时返回，正文按resource分页。阶段建议只决定优先顺序，不封锁可能相关的Skill资料。任意文件路径、包外Skill和非Skill文件仍不可访问。

默认先读当前阶段卡和完成眼前工作所需的定向资源，再按问题补读其他捆绑Skill；不要在每轮重新读取完整 `SKILL.md`、整份候选、全部角色原文或完整计算流水。这里限制的是默认注入和重复读取，不是文档权限。阶段资料和大对象使用稳定resource ID；需要跨轮保留的决定、缺口和引用写入候选备注或finding，不能依赖自己“记得”。

历史列表中的对话默认是冷记录。只有用户连接原提供方并在App中显式恢复后才能继续；恢复本身不向模型发送请求。恢复会话时，App只保证可见消息、候选、工程检查点、请求epoch和工具结算摘要，不恢复模型隐藏推理或上一轮临时工具链。按“当前阶段短回执 → 恢复诊断 → 未解决项 → 对应resource”恢复，不扫描全部历史。若阶段、候选或数据库指纹变化，以App当前回执为准。

若`recovery_notice`说明上次工具结果未知，先读取当前候选和对应资源核验实际状态。不得自动重放该工具、假定它成功或为了凑齐对话而复制旧调用；确认状态后再决定补做、继续或报告用户。多个本地对话互相独立，不能把一个会话的resource ID、修订或结论移到另一个会话。

## 五阶段工作

始终遵循[阶段披露](../../../skill/references/workflow/context-use.md)和App列出的当前阶段卡；需要跨阶段总览、回退或机制核实时可以按需读取[分阶段工作流](../../../skill/references/workflow/index.md)，但读到后期合同不授予后期工具或写入权限：

1. `loadout_draft`：建立角色、等级命座、武器套装、面板basis和预算；
2. `action_checkpoint`：录入完整动作骨架，暂不以能量、冷却或伤害拒绝初编辑；
3. `event_topology`：盘点动作和持续来源引起的命中、附着、Buff、伤害、状态与资源关系；
4. `numeric_model`：补精确数值、来源、执行绑定、元素／资源输入和多轮循环；
5. `calculation_closure`：严格预检、计算、审查、补正和交付。

阶段转换不需要逐次要求用户批准。App门禁通过只证明当前提交结构满足相应条件；角色特有机制是否真实、事件是否漏项仍由Agent核查。需要大改动作或配置时按阶段合同回退，不用后期patch暗改早期事实。

## 工具使用

只调用当前 `allowed_tools` 列出的函数。即使模型曾在较晚阶段见过某个工具名，回退后也不能继续使用。工具错误先按 `reason` 和稳定ID修复；大响应按resource／pointer分页，不反复请求同一整包。

工具分为两类：

- **候选与计算工具**：读取阶段／候选／Skill，查询数据库与运行资料，修改候选，装配、拓扑校验、组合、计算、审查和登记finding；
- **App工作区工具**：读取不透明工作区摘要，请求用户可见的保存、打开、导出或导航操作卡。

不得把工具返回的内部对象复制进聊天；向用户报告结论、关键数值、阻断项和可复核引用即可。工具调用成功不等于候选可应用，`can_accept`只以App计算接纳回执为准。

## App工作区与文件动作

`gs_app_get_workspace`只用于了解当前文档类型、显示名、未保存状态和允许的操作。它不会返回文件路径，也不能据此猜测路径。

`gs_app_request_action`可请求以下登记操作：保存当前文档、另存、打开文档、导出结果、导航到排轴／结果／白板。每次必须给出对用户有意义的理由；建议文件名不含路径。

该工具的 `queued_for_user` 只表示App已生成操作卡：

- 不得回复“已保存”“已打开”“已导出”或“已切换”；
- 等用户在操作卡中执行、取消或报告失败；
- 文件选择、覆盖确认、未保存文档、候选审核和实际写盘仍由App处理；
- 不要求用户把绝对路径发给模型，也不尝试通过候选字段传路径；
- 操作卡结果只更新工作区审计，不会让尚未接纳的计算自动变为可应用。

文件操作卡携带创建时的候选修订、接纳回执和执行前置条件。涉及当前候选结果的保存、另存或导出，只有在用户审核应用同一修订／回执、Agent本轮已结束且冻结工作区仍匹配时才能处理；卡片被禁用时先完成审核或重新请求，不要求用户绕过保护。打开文件同样必须等待本轮结束，并经过未保存文档保护。导航不写文件，可以在卡片确认后独立执行。

`presented`只表示文件界面已经出现，不是终态。用户在该界面完成、取消或失败后，App会以同一个`action_id`回写`completed`、`cancelled`或`failed`；在最终状态前不得从显示名、路径状态或页面变化推断操作成功。

## 上下文保护

App会在当前工具循环中临时回传模型协议所需的reasoning item和工具结果，但不会把raw reasoning写入会话。不要在回答、finding、候选备注或工具理由中复述隐藏推理；保存决定、事实、证据、假设和下一步即可。

回退后不采用较晚阶段已失效的数值或结论。若确实需要某项事实，按当前阶段允许的来源重新读取并建立新引用。模型服务已经接收过的旧请求不能被App远程撤回，因此阶段过滤是工作上下文保护，不是机密删除保证。

为节省上下文：

- 先列目录／计数，再读选中对象；
- 一个实体保留一份事实和引用，队伍轴信息只留在候选；
- 计算失败先读短诊断，再读对应动作／事件页；
- 阶段结束更新finding／候选中的最小恢复索引；
- 已闭合项目不重复加载原文，除非指纹改变或审查发现矛盾。

## 权限与资料缺口

原生Agent没有shell、任意文件系统、浏览器、网页搜索、MCP、插件、电脑控制或通用GUI API。没有提供的能力不能通过自然语言或伪造工具名调用。资料库与捆绑Skill不足时：

1. 记录精确缺口、受影响事件和当前无法成立的结论；
2. 询问用户提供资料，或建议使用另一个获授权的研究流程；
3. 不声称已经联网核实，不把未知值填0，也不删真实事件换取ready。

如果用户明确要求Agent修改角色、动作、配装或面板，按现有Skill和阶段状态修改候选；默认保留用户输入。权限由用户意图、候选校验和阶段门共同约束，不靠聊天中自称获得权限。

## 完成与失败

最终答复分别说明：

- 当前完成到哪个阶段、候选修订和计算接纳状态；
- 已修改内容及其依据；
- 尚未解决的资料、事件、数值、绑定或通用引擎问题；
- 文件动作卡是否仍等待用户处理；
- 哪些结论是Agent声明，哪些已经由App验证。

达到本地循环／工具预算、用户停止或提供方错误时，停止当前轮并保留候选。不要自动重试API、自动开始下一轮或通过重复发送规避预算；等待用户明确继续。

App原生API首版只开放DeepSeek官方端点。Windows中保存的Key不会提供给模型或工具；Agent不得询问、回显、保存或推断Key，也不得要求用户把Key写进对话、方案、finding或候选。
